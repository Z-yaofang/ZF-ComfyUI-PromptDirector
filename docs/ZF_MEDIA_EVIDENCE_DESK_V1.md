## 操作

1. 点击「导入素材」多选图片、视频和音频，或将外部文件拖入素材池。所有类型放在同一素材池，可滚动浏览。卡片右上角「×」卸载资产及其全部轨道引用，仅修改项目；可撤销恢复，不删除磁盘原文件，不自动播放恢复的资产。
2. 点击素材，在中央监看器预览；音频显示解码得到的真实峰值。拖到对应轨道，或点击右侧固定操作位的「加入对应轨道（播放头处）」。目标轨显示高亮及释放提示，错误轨显示类型提示；外部文件拖错轨道时保留在素材池。
3. 图片是固定宽度的排序卡片，没有视频时长。图片和视频卡片显示缩略图及文字遮罩；独立音频与视频原声卡片显示按源入/出点截取的峰值波浪线。视频和音频使用同一秒时间轴；时间线为横向滚动条预留高度，默认三轨完整显示，整体没有纵向滚动。重叠片段分行显示，超过三行时仅在该轨道内滚动。
4. 拖动片段移动；拖动两侧把手裁剪。右侧可精确输入源入点、源出点和轨道起点，单位均为秒。数字框首次获得焦点/点击会全选，同一焦点中的后续点击可放置光标。拖动把手受实际源边界限制；数值输入的无效裁剪保留并报错。
5. 点击时间尺或拖动黄色播放头定位；黄线保持细线，透明命中区宽 16 个节点像素，带三角手柄和横向调整光标，优先于青色窗口响应。拖动中实时更新选中片段的源预览。选择轨道片段后，右侧同一操作位变成「删除此片段」；工具栏保留分割、撤销与重做，删除也可用 Delete/Backspace。坐标换算支持 ComfyUI 画布变换；吸附距离为实际屏幕 7 像素，由时间网格的屏幕宽度与布局宽度换算，可关闭。黄色播放头吸到 H3 窗口起止和片段边缘后，最终时间、预览时间与源帧读数都使用吸附后的值。
6. 含音频的视频默认生成绑定原声。绑定时移动、裁剪、分割作用于整组。工具栏“分割”的提示说明在播放头处分割；视频轴“删除”删除所选视频及绑定原声，保留已解绑音频。音频轴“删除”只删除所选独立音频；绑定原声须先“解绑音频”，键盘Delete/Backspace与检查器同样拒绝单独删除它。未选对应轨道时该轴按钮禁用。每次删除可撤销/重做，素材池与磁盘源文件保留。原声参与协议保持，开关不再占用视频轴操作位；解绑后音频可独立编辑，也可重新绑定仍存在且没有其他原声绑定的原视频片段。
7. 青色 H3 处理窗口支持整体拖动和两侧缩放；两侧可反向吸到黄色播放头或片段边缘，整体拖动由距离最近的任一侧吸附并保持窗口长度。拖动保留 24 fps 量化，非帧边界的播放头对应到最近 H3 帧；阈值先按未量化的拖动位置检查，不会因量化把超出阈值的点误判为命中。关闭吸附只保留帧量化；拖动不产生负时间。项目级数值区独立放在时间线与状态提示下方，右侧 inspector 不再包含 H3 字段。底部两行紧凑显示开始/结束秒数、只读总时长、起止帧、总帧、fps 及合法/超限状态；数值输入与青色窗口双向实时同步，首次聚焦同样全选。窗口固定 24 fps、48–360 帧、最多 15 秒。超限保留原值并显示错误，不自动截断，整个项目和源素材可以长于 15 秒。
8. 工作流保存 `project_data` JSON 和视图状态（选择、播放头、缩放、水平滚动、吸附）。重新打开后后台重新核实素材事实和编号。撤销历史只保留当前编辑会话最近 100 次，不写入工作流。可另行导出项目 JSON。

9. 「截图」截黄色工程播放头处的视频选段。先暂停并冻结点击时来源及源时间，再由CPU解码原视频单帧，保留原像素尺寸和方向；不用12fps代理、封面或GEN画布裁图。裁剪后的工程/源时间映射及分割接界与时间线监看一致；空白区、仅图片/音频或池中视频尚未入轨时禁用。成功只追加统一素材池，不自动入图片轨、不选首尾或改变采访。可把新图片按普通图片拖入图片轨，再选择首帧/尾帧或参考图。

截图显示红色 `image`，普通图片显示黄色 `picture`，视频显示绿色 `video`，音频标记保持。文字和检查器同时说明截图身份；内部截图仍为 `kind=picture`，与普通图片共用轨道、出口、检测和预设。`capture`来源元数据由服务器注册库核验，不能根据文件名推断；刷新与保存后保持。池删除/撤销保留截图PNG原件，截图独立于原视频，可再用。

截图与上传共用单次导入锁，媒体worker最多并发2项，单次解码最长30秒。按钮忙碌时显示状态并禁用重复操作；异步期间移动播放头或换选择仍取冻结的位置。来源被移除、重新载入项目或节点移除后的旧响应不加入当前项目；失败只清本次新文件，已有素材/库不改。已完成而被前端丢弃的响应与普通导入相同，保留已登记的完整PNG，不将其自动加入任务。

Windows文件暂时占用时清理最多尝试两次，锁始终释放。持续无法清理会明确报错“未能全部清理”，不能视为成功截图；已登记记录若无法回滚则保留完整PNG，避免留下指向不存在图片的记录。此时已有用户素材仍保持，可稍后解除占用再检查本地素材目录。

池卡和轨道卡内部图片均禁用浏览器原生拖动。素材卡 `dragstart` 清空 DataTransfer 后只写 `application/x-zf-media`，不携带 URL、文本或文件数据；本取证台发起的拖放在框外释放会取消，并阻断外部画布 drop。只有该次内部拖放期间才安装捕获监听，结束后移除。不会清理用户画布上此前意外创建的「加载图像」节点，也不会影响没有内部拖放时的外部文件导入。

监看器预览源素材，而非合成播放整条时间线。视频预览使用 12 fps 静音代理，并单独同步原声音频。监看器与素材检查器采用相同的源帧措辞：仅在 `frame_count_exact=true` 且 `vfr=false`（已完整探测且时间戳稳定）时显示「源帧」；VFR、未完整探测或稳定性未知时均显示「估算帧」，并保留总帧数与源 fps。帧读数由源时间和源 fps 映射，不表示 12 fps 代理逐帧复现原视频。裁剪仍以原文件的秒数为依据。

## 数据契约

机器可读定义：[`zf-media-project-v1.schema.json`](../schemas/zf-media-project-v1.schema.json)，`schema_version: 1`。不包含采访问题、用途推断、H3 提示词或生成模型参数。

| 字段 | 含义与所有者 |
| --- | --- |
| `project_clock.fps` | 工程显示时钟，默认 24；独立于源帧率和处理窗口时钟 |
| `output_canvas` | 可选的统一消费画布；由素材台 `width` / `height` 成对输入写入，视频出口默认继承 |
| `assets` | 稳定 `asset_id`、类型、显示名、安全 `source_handle`、探测事实 |
| `assets[].capture` | 可选的已注册视频截图来源/请求源秒/实际帧PTS/工程秒；仅UI区分image，内部仍picture，canonical覆盖客户端声明 |
| `picture_track` | `item_id`、`asset_id`、`order`；不伪造时间长度 |
| `video_track` | `clip_id`、引用资产、轨道起点、源入/出秒数、原声开关及绑定 ID |
| `audio_track` | 同样的秒窗口；`origin` 为 `standalone` 或 `video_source`；含开关、当前绑定和原视频片段 ID |
| `processing_window` | 起止秒、fps；起止帧及帧数由后台计算，仅用于适配预览 |
| `label_map` | Python 唯一生成的编号映射，前端和两个节点输出消费同一结果 |
| `validation` | 结构化 `errors` / `warnings`，每项包含 `path`、`code`、`message` |

时间区间为半开区间 `[in, out)`，秒数是权威值。帧映射统一为 `floor(seconds * fps + 0.5)`。裁剪片段还输出源入/出帧、源帧数、工程帧数和估算标志；这些派生字段以及已有 `label_map`、`validation` 每次都会重新计算，不相信工作流内旧值。

图片按顺序，视频及独立音频按时间轴起点排序；起点相同以稳定片段 ID 排序。每次删除或重新排序后，分别连续生成 `Picture 1…`、`Video 1…`、`Audio 1…`。绑定原声使用 `Video N 原声`，不占独立音频序号。原始资产可被多个片段引用，编号属于轨道项。ID 不因排序、裁剪或移动改变，分割右半段产生新 ID。

前端提交编辑后显示编号同步状态，只有 Python 正规化结果生成编号。保存/导出的 JSON 和节点执行会再次正规化。结构无效的 JSON 拒绝处理；合法结构内的超限窗口、缺少源素材或错误裁剪通过 `validation.errors` 表达，节点仍输出可审阅的计划，不执行裁剪或推理。

## 存储、媒体服务和限制

所有原文件及缓存都在 ComfyUI 的 `input/zf_media_evidence/` 下。`originals/<32 位随机十六进制 ID>.<扩展名>` 是唯一允许的来源句柄；不接受绝对路径、URL、路径穿越和逃逸目录的符号链接。显示名只作文本使用，不决定存储路径。探测登记记录在 `cache/`，节点执行按该记录重新填入真实事实，并检查源文件大小和修改时间。

| 限制 | V1 值 |
| --- | --- |
| 单文件 / 原素材总量 | 512 MiB / 8 GiB |
| 图片、视频尺寸 | 最大 50,000,000 像素，单边不超过 16,384 |
| 视频、音频源时长 | 正数，最长 3,600 秒；无法确认时长时拒绝导入 |
| 源视频帧率 | 大于 0，最高 1,000 fps |
| 音频 | 最高 768 kHz、64 声道 |
| 并发 | 单批上传；最多 2 个媒体子进程，缓存生成串行以避免半成品暴露 |
| 探测 / 波形超时 | 每项 30 秒 |
| FFmpeg 预览超时 | 每项 90 秒；超时不输出截短预览 |
| 工程 | 最长 12 小时时间轴；128 个资产，每轨最多 512 项 |
| JSON | 2 MiB，最大 32 层；拒绝重复键和非有限数值 |

支持静态 PNG、JPEG、WebP、BMP；MP4、MOV、MKV、WebM、AVI；WAV、MP3、M4A、FLAC、OGG。实际类型由解码后的流决定，扩展名不直接证明类型。动画图片、播放列表和不能解码的来源拒绝导入。文件容器显式指定，允许的媒体协议限定为本地文件/管道，不增加互联网请求。

Pillow、PyAV、NumPy 由 ComfyUI 环境提供；FFmpeg 从已有 PATH 或已有 `imageio_ffmpeg` 包解析。没有添加依赖或自动下载。缺少能力时返回结构化错误。子进程仅用于本功能发起的媒体作业，超时由该作业终止逻辑处理。

视频代理为最长边限制在 480×270 框内、12 fps、H.264、无音轨；原声/音频预览为 AAC。波形由实际解码音频转单声道 8 kHz 后聚合 1,024 个绝对峰值桶。缓存不替代原文件。删除轨道项和撤销导入不会删除磁盘原文件；V1 不提供原文件清理操作，也不自动清理缓存。

前端每个节点按来源句柄和预览类型缓存缩略图 Blob URL、峰值数据及在途请求，最多 256 项。监看器和轨道复用峰值；拖动、裁剪、缩放和重绘不重复请求同一缓存。轨道波浪线由源区间内实际绝对峰值聚合绘制，是峰值包络示意，不表示原始音频相位。单个波形画布最多 2,048 像素、512 个采样点；请求失败缓存为空结果，降级为中线且不影响编辑。重新加载前端可重新请求失败项。节点移除时中止本节点在途视觉请求并释放 Blob URL，磁盘缓存仍保留。

本地端点：`POST /zf-media-evidence/upload`（单文件 multipart）、`POST /zf-media-evidence/normalize`（项目 JSON）、`GET /zf-media-evidence/preview`（来源句柄及 `original` / `thumbnail` / `proxy` / `audio` / `peaks`）。跨来源 Origin 拒绝；错误采用 `{ok:false,error:{code,message}}`，不回显绝对路径。浏览器预览可利用 FileResponse 的范围请求。

## 后续适配边界

后续采访节点应消费 `ZV_MEDIA_PROJECT`，在自己的适配层将轨道项 ID、来源句柄、秒窗口和 `label_map` 映射到模型契约；先处理 `validation.errors`，不能把 12 fps 代理帧当成源帧。H3 的持久编号规则与本节点的连续重排编号不同，必须显式映射，不能改写阶段 1 的编号策略。
