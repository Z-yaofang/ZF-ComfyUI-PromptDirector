# ZV H3 采访表 v2（H3-V2-04）

素材台导入、排序、选择源片段、设置目标 GEN 窗口和统一宽高；采访表保存创作文本、机械绑定和语义用途；H3 专属固定出口在执行时导出真实媒体。

## 用户预设与来源引用

“我的采访预设”是主入口。命名后保存新预设；选择一项可载入、更新、改名或删除，多选可导出一个JSON集合，导入会创建新本地UUID，重名显示副本后缀。库在当前 ComfyUI 用户目录下的 `zf_h3_interview/presets.sqlite3`，与素材台处理预设分开，正常重启后仍可引用。版本冲突会提示重新载入，不覆盖库里他人的新版本。删除只删库条目，当前表格与所有素材保持。

模板按素材台同类位置匹配当前新ID，缺项列出并保留待补齐用途，多余项保留当前参与状态；预期数量只作提醒。视频槽保存原声期望、标签与自由用途，但不会暗开/关闭原声，不会将缺失原声替换为独立音频。等待原声时，已匹配视频及用途中的各引用保留来源ID；之后重排、补声或导出，仍指原来源。导出反查当前同类槽位，不复用旧位置。物理接口变化需要重新检测；只加载语义保持已有机械对齐。旧配方折叠为可选教学示例。

初次载入记录各待补齐槽的 `existing_item_ids`。后来新增素材按当前同类排序依次匹配剩余逻辑槽；已匹配ID加入其余同类槽排除集，不再被另一槽占用。全局引用和待补齐用途共同使用这次匹配结果，前插/重排不覆盖旧素材用途。旧候选state缺少初次来源记录时明确要求重新载入原预设，不按当前旧槽位猜ID；已有完整匹配state和可携带模板schema不变。

只识别完整、大小写精确的 `<Picture N>`、`<Video N>`、`<Audio N>`。中文“图一”、裸 `Picture 99`、普通数字和时间不推断、不改写。保存显式引用前要检测，确认当前来源；可在素材卡片点击“插入”当前标签。模板将引用转换为 typed slot+bank 的受限token，不携带旧H3号码或真实ID。当前工作流保存stableID+bank来源，检测改号后重渲染。因此新增首帧后原参考Picture1可以变Picture2，新增视频原声后独立Audio1可以变Audio2，仍指向原来源。

缺来源/物理bank/同源原声时保留 `<H3待绑定:rN>`，不删句子、不指向另一个合法编号。实际送入模型的未解析引用硬拒；停用purpose沿用未使用提醒。已确认绑定、后来停用的purpose可以保存，并在重新参与后恢复编号；从未能反查来源的字面显式标签须先修正或检测。用户编辑文本会保留已有标签对应来源，改删标签会更新/解除绑定；解析失败保留新原文并提示。加载/检测等待期间若文本、用途或素材改变，过期成功或失败响应均不应用，最新编辑和已有机械对齐保持；并发检测旧响应和已移除节点响应丢弃。当前有效请求确实失败时仍明确报错。

预设请求/导入/导出集合最多2 MiB，每批最多256项；库本身无128项或单次存档槽位限制，列表每页最多100项。普通单项文本最多12000字符，引用/待绑定渲染保留最多16000字符，每项最多128引用；当前工作流采访JSON（含快照、引用和待补齐项）最多256 KiB，超过会明确报错。损坏库或事务失败保留原库；路径链接/reparse/hardlink拒绝访问。非法导入后可重选同一文件。

## 检测与创作

1. 保持素材台 → 采访表 → `ZVH3ReferenceOutlet` 以及 LOW/HIGH/Stage①的已有模板接线。
2. 点击“检测并对齐素材”。新素材默认参与：图片 → `ref_images`、视频 → `ref_videos`、启用的独立音频 → `ref_audios`。启用的视频原声只使用同编号 `ref_video_audio_N`，绑定原声卡片也保持可见。
3. 每项素材分别选择参与状态和物理接口。首帧、尾帧、驱动音频必须明确选物理用途；图片可明确多接口，首尾加参考显示“混合参考”，内部仍为Hybrid兼容路径。本次编号由物理槽顺序和素材台排序决定。
4. 填写任意创作要求、多个语义标签和每素材自由用途。内容可留空；语义与旧配方均不改变路由或检测状态。一个素材可定义多个 Subject，编号不会因此增加。
5. 预览复用素材台已有缩略图、视频代理、音频缓存和波形；整表使用一个共享播放区。音视频从卡片标注的“原片源入”播放到“出”并暂停；绑定原声与所选视频同段同步。分割、裁剪、删除后的当前轨道片段逐项展示，同源两段不会合并，也不会从素材池补满接口。未参与项仍可见。

状态分别显示路由对齐、模型硬错误与语义/本地兼容提醒。显式引用不存在的 Picture/Video/Audio N 是硬错误，并列出正确编号。检测会同步两支可写 widget 的 task_type=auto、add_source_as_reference=true、prompt_primary_audio_ordinal=0；没有 drive_audio 时同步 audio_mode=native。不会更换模型或改接线，动态参数和 audio_mode 分支冲突需要用户按错误原因处理。

素材、顺序、参与、物理接口、原声状态、尺寸或窗口改变后重新检测。服务器使用同一计划器校验，并在执行时重新检查对齐上下文与当前接线；不会从语义角色重建另一套路由。

04检测读取素材台实际成对宽高，支持静态核心ResolutionSelector、PrimitiveInt/INTConstant和字面值，不执行任意上游节点。未知动态、单边或非法尺寸提示“尚未核实”，不会显示已对齐；同尺寸静态节点替换不误判过期。正常重启ComfyUI并刷新前端后生效。HTTP检测与执行分别重新核验源文件size/mtime；不信任客户端validation，已准备的出口计划在导出前也核实来源。

## 参考段与输出时间

目标输出以素材台 GEN 窗口为准：官方 4–15 秒、24 fps，起止及帧数对齐 24 fps 网格。单窗口策略必须兼容；本工单未加入分段执行器。

H3 参考视频/音频取素材台已经选择的 source_in/source_out，不强制与 GEN 窗口相交，可用于补开头、续写或中间转场的前后上下文。每段 2–15 秒，视频总长 ≤15 秒，独立参考音频总长 ≤15 秒；配对声轨不计独立音频总长。不会自动使用无限长原文件。H3 出口通过专属调用窗口取得片段，普通素材/混音出口继续保留原来的窗口交集语义。

本地 T8 输出 length 向上对齐 17n+5：目标 15 秒/360 帧对应 362 帧。校验读取 LOW/HIGH 的实际 length 字面值，或确认同一素材台 → 窗口出口 frame_count → 已知 17n+5 数学表达式链路。实际 length 与 GEN 对齐目标不符、LOW/HIGH 长度不同均为硬错误。任意未知动态链路不执行表达式，明确标为实际 length 未核实、按 GEN 假设预测。

参考视频先截到实际 model length，再向下对齐：合法 2 秒出口 48 帧可变为模型输入 39 帧；15 秒参考在已核实 length=124 时只可见 124 帧。报告区区分 requested、出口帧数、length 证据和模型输入预测。核实参数仍不代表已验证 GPU 成片。

## 官方与本地接口

规则集中在 `h3_focus/rules.json`，同一后端计划器提供前端验证和来源说明。

- 官方 Ref2VA：参考图片 ≤9、视频 ≤3、独立音频 ≤3、混合输入 ≤12 项。按实际发送的图片槽、视频片段和独立音频片段计数；不按角色或 filename 去重，同源视频原声不双计。显式同图多物理口仍是多个实际输入项。
- 本地固定出口保留首帧、尾帧、9参考图、3参考视频、3配对原声、drive/final音频、3独立参考音频、manifest/report，共24个输出；顺序、类型及空值 None 契约保持。
- Comfy/T8 分开接收3个配对原声通道和3个独立音频通道，可形成 Audio 6；加显式驱动音频可形成 Audio 7。每组总长分别检查；此组合超出官方文档明确说明时标为本地兼容路径。
- 首尾锚点加 refs 属于 T8 Hybrid，drive_audio 或仅独立音频也标本地扩展。Hybrid 任务不等同实验 Hybrid 混权加载器；匹配模型与 T8 布局兼容仍须确认。
- 6图3视频3音频只是常见布局，不是数量配方或硬上限，也不承诺任意该布局组合都符合12输入限制。

## v1迁移与预留模板

`zv-h3-interview-v1` 显式迁移为 v2，保留原文本（包括空白）、recipe/mode备注、旧语义选择及检测快照。有真实旧快照时以实际物理端口为准，旧语义首帧标签不会额外增加端口。没有快照时明确首尾+参考用途转换为多bank，并一次性保留旧逻辑中首个确定的 speech_lipsync/audio_reuse 独立音频为 drive_audio。有明确旧选择或有效snapshot时冻结当前未选项；有效空snapshot保留零参与/零出口。无roles且无snapshot的空v1按fresh未确认候选处理，有媒体执行仍须先检测。之后新加入的v2普通素材默认参与。迁移幂等，v2 重读不从 roles 反推。

旧快照缺少当前素材上下文时必须首次手动检测，固定出口和旧独立出口执行均拒绝沿用无 alignment 的媒体快照。全局创作文本和实际发送素材的自由用途会校验显式编号；未参与或已删除素材的用途只提示未使用，不阻止模型。

v2的 `bindings[item_id]={item_id,participates,banks}`、`media_purposes[item_id]` 和 `alignment` 保持。02新增 `reference_texts` 保存受限canonical token、当前来源与最后渲染文本，`preset_pending` 保存未匹配槽位/原声用途及各用途的实时引用定义；03补初次来源排除集，均随工作流保存。最终可携带模板为 `zv-h3-interview-preset-v1`、多项集合为 `zv-h3-interview-library-v1`；由原typed-slot helper扩展，12类字段、导演侧重、参与/banks/roles/purpose与视频原声语义都保留，不保存真实ID、文件元数据、路径、缓存、快照、尺寸或窗口。预设 CRUD 已实现，分段执行器和实际GPU生成留待后续验收。

代表组合、只读审计、分享准备与环境交接见 [H3 v2 使用交接](H3_V2_HANDOFF.md)。

采访表仍输出原有8项及末尾的 `reference_plan`，固定出口仍为24项。最终提示词由连接的语言模型生成；本节点不做 H3 GPU 生成。
