# 动态多路选择：文字、图片、视频、音频

旧节点 `ZF文本动态多路点选` 保留原名和接口。新增三个 `ZH`（Help 辅助工具）节点，使用相同的单选按钮面板：

| 节点 | 数据接口 | 选择 0 时的输出 |
| --- | --- | --- |
| ZF文本动态多路点选 | STRING | 空字符串 `""`，不是 None |
| ZH动态多路图片 | IMAGE | `None`，不是黑图 |
| ZH动态多路视频 | IMAGE 视频帧批次 | `None`，不是零帧视频；不含音轨 |
| ZH动态多路音频 | AUDIO | `None`，不是静音音轨 |

## 按钮与整数控制

- `input_count` 设置可见入口数量，最多 32 路。只选择一路；没有经过当前节点被选中的支路不会因这个选择器而执行。若该上游另接了保存／预览等独立输出节点，仍可能由那条输出路径执行。
- `selected` 不接线时由按钮决定；将它转换为输入并接入整数后，以外部整数为准，按钮不再覆盖它。`0` 就是空按钮，`1～当前路线数量` 对应同编号入口。
- **只有 4 路却输入 `5` 属于误输入，必须报错。** 不自动增加入口，不退回第 1 路或最后一路，也不把越界当作空选项。请改成合法整数，或主动增加路线数量并接好对应素材。
- 选中了范围内但未连接的入口时，输出空内容并保留该路线索引；例如已配置 5 路而第 5 路未接素材，`selected_index` 仍是 `5`。只有主动选 `0`，索引才是 `0`。
- 能明确读取的简单整数常量会在面板中显示实际选择或越界错误；计算节点等运行前不能确定的整数显示“执行时决定”，执行时同样检查范围。面板不会把保存的手动按钮当成实际路线。运行后的 `selected_index` 输出可供下游使用。
- 缩小入口数量后，若原选择超出范围，保留原值并提示错误，不偷偷换路；请改选保留范围内的路线或 `0`。断开外部整数后恢复原手动选择。
- 数据原样通过，不复制图片、不解码视频、不重采样音频。未选择的素材输入采用 lazy 执行；空选项不会请求任何素材分支。外部整数本身仍需计算。

## 接 H3 时，空值代表什么

在已检查的本地 MiniMax H3 Audio T8 实现中，首尾帧及参考图片、参考视频、参考音轨、独立参考音频支持 `None`，表示这一项未提供。选择器不使用会阻断下游执行的 `ExecutionBlocker`，也不制造假媒体来填口。

但 `None` 不是所有节点都能接受的通用“防报错数据”。H3 仍需要满足当前模式：

1. **参考视频与原声配对：**关闭 `ref_videos` 的某一路时，同编号 `ref_video_audios` 也应置空。可以用同一个整数同时控制视频和音频选择器；有视频、无原声允许，只有原声、无对应视频会报错。
2. **首尾帧和参考模式：**固定首帧／首尾帧／参考生成模式仍要求相应素材存在。没有任何参考时，应使用匹配的文生模式或 `auto`，不能仍强制要求参考生成。
3. **驱动音频：**`drive_audio` 为空时，已检查的 T8 实现只允许 `audio_mode=native`；`lock_source`、`remix_source`、`reference_only` 都要求驱动音频。普通参考音频口为空不等于驱动音频模式也自动改变。
4. **提示词编号：**关闭素材后，提示词中不要继续引用不存在的 `<Picture N>`、`<Video N>`、`<Audio N>`。剩余素材编号需与 H3 实际整理结果一致；选择器不会自动修改提示词或采访表计划。

H3 的参考视频接口接收 **IMAGE 视频帧批次**，按 24 fps 解释。原生 `VIDEO` 可先用 ComfyUI 的 `GetVideoComponents` 拆成 `images`、`audio`、`fps`，再分别接视频和音频选择器；该拆分节点和本选择器都不会自动把素材帧率转为 24 fps。需要适配时，请在素材台／视频加载阶段设置参考帧率。

旧节点名称和范围内的已保存选择保持兼容。旧版本把超出当前入口数量的整数夹到别路的行为改为明确报错。云端与本地共用实现，不引入新媒体依赖；更新 RunningHub 时仍须同时发布后端与前端资源。上述 H3 空值行为依据本机源码核查，新节点尚需在实际云端版本验收。
